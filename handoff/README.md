# 引き継ぎ書：MR日報の自由記載から皮膚科医の評価とネックを定量化する検討

作成：2026年11月19日。個人のClaudeアカウントで行った調査、設計、試作を、職場のClaudeアカウントで続けるためのまとめです。

## 1. 目的（依頼の内容）

- MR日報の自由記載から、皮膚科医ごとに自社品への評価とネック（処方の障壁）を洗い出し、定量化する。
- 医師をカテゴリに分け、将来を予測する。「こうすれば変えられるかも」という提案も出す。
- 疾患領域の異なる他の自社品（皮膚疾患の複数の製品）の情報も加味する。
- 参考：インテージテクノスフィア「文意知 for MR日報コメント」（トピックの確率で文を数値化）の考え方が近いと考えている。

## 2. 確認できている前提

| 項目 | 内容 |
| --- | --- |
| 対象の医師 | 皮膚科医。複数の皮膚疾患の自社品を紹介している |
| 医師の識別 | 日報は医師を選んで記録する（医師IDが付く） |
| 日報の量 | 年間数十万件以上 |
| 売上データ | 施設ごとの納入・売上 |
| 医師ごとの採用 | 一部の製品に投与症例登録があり、医師名が記載される（分析に使えるかは未確認） |
| 実装環境 | Python。社内にGPUがある。データは社外に出さない |

未確認の前提（院外処方の売上の扱い、施設の要件、製品ごとのMR体制など）は、設計書の「前提」の節にあります。

## 3. 行ったこと（時系列）

1. **公開事例の調査**：日本の製薬（外資を含む）で、日報の自由記載から医師情報を定量化した事例を、企業・ベンダーの公開情報、論文・学会発表、特許から調べた。主な出典は本文を確認済み（会員限定の記事など5件は未確認）。
2. **実装とモデルの調査**：各事例で使われたモデルと実装、追加の事例（他業界の営業日報を含む）、社内で動かせる日本語・医療向けのモデルを調べた。
3. **分析の設計**：依頼の目的に合わせた設計書と、インテージへの質問リスト15問を作った。
4. **試作のPythonコード**：架空のデータで、抽出から予測、施策の効果の推定までを通して動かす試作を作った。
5. **敵対的レビュー**：調査・設計書と試作コードを、別のAIエージェントが敵対的にレビューし、指摘を反映した。コードは修正後に再検証した。

## 4. 主な結論

- **公開事例**：手法と成果まで公開した国内製薬の事例は、ほとんどない。医師の定量化に最も近いのはJストリーム（2026年10月発表、導入実績は非公開）。日報を定量化して売上と結びつけた具体例は、武藤猛氏の講演資料（2016年、日報2万件、営業所単位の回帰）だけ。
- **文意知の位置づけ**：「どんなネックがあるか」を見つけるのには向くが、評価の正負（肯定的か否定的か）は分からない。設計では、文意知に近いトピック抽出を最初の段階（観点の洗い出し）に使い、その後は項目を決めて社内のLLMで抽出する。
- **設計の要点**：
  - 医師の情報を2層に分ける（製品ごとの評価・ネック・段階／製品をまたぐ医師の特性）。
  - 予測力と施策の効果は、MRが書かない結果（施設の売上、症例登録）で判定する。日報上の段階は練習用。
  - 観察データからの効果の推定は、試す施策を選ぶためだけに使い、訪問計画（施設かMRの単位でくじで分ける）で確かめる。
- **最初に確認すること**：
  1. 日報の安全性情報（副作用の記載）の扱いを、安全性部門と決める（過去の日報を全件解析すると、未報告の副作用を会社が把握することになるため）。
  2. 投与症例登録のデータを分析に使ってよいか（法務、安全性部門、信頼性保証部門）。
  3. 日報100〜200件を読み、医師の評価やネックがどのくらい書かれているかを確かめる。
  4. 日報の指標が医師の差を測れているか（担当MRが交代した医師で、医師による差とMRによる差を比べる）。
- **試作の結果（架空データ）**：自由記載を足しても予測は良くならず、施策の効果は補正しても大きく出た。手法の動作確認であり、実データでの効果を示すものではない。
